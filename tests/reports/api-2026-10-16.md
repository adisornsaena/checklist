## รายการบั๊ก (FAIL)

### B1 — token เดิมยังใช้ได้หลังปิดใช้งาน / ย้ายหน่วยงาน / ลดสิทธิ์ — ความรุนแรง: **สูง**
- สาเหตุ: `server/src/auth.js:12` ฝัง `id, role, orgId` ลง JWT และ `server/src/auth.js:19` (`requireAuth`) ตรวจแค่ลายเซ็น ไม่อ่าน `users.active/role/org_id` จากฐานข้อมูล ส่วน `requireAdmin` (`auth.js:26-27`) ใช้ role จาก token มีแค่ `GET /api/auth/me` (`index.js:34`) ที่ตรวจ `active`
- ขั้นตอนทำซ้ำ:
  1. admin `POST /api/users` สร้าง staff okmd แล้วล็อกอินได้ token T
  2. admin `PUT /api/users/:id {"active":false}` → `GET /api/cases` ด้วย T ได้ **200** (ควร 401) และ `POST /api/cases` ยังทำงานได้
  3. หรือ `PUT /api/users/:id {"orgId":<ndmi>}` → `GET /api/catalog` ด้วย T ยังได้ `okmd`
  4. หรือ admin ชั่วคราวถูก `PUT {"role":"staff","orgId":1}` → `GET /api/users` ด้วย token เดิมได้ **200**
- ผลกระทบ: พนักงานที่ถูกปิดบัญชีหรือถูกถอดสิทธิ์ admin ยังทำงานต่อได้นานถึง 12 ชั่วโมง (อายุ token)

### B2 — เปลี่ยนสถานะไม่ตรวจสถานะเดิม (cancel / reopen) — ความรุนแรง: **กลาง**
- สาเหตุ: `server/src/index.js:264-285` ตรวจ `c.status !== 'open'` เฉพาะ `close` (บรรทัด 270) ส่วน `cancel` และ `reopen` เปลี่ยนสถานะได้จากทุกสถานะ และ `index.js:281` ล้าง `closed_at` เป็น NULL
- ขั้นตอนทำซ้ำ:
  - `POST /api/cases/:id/close` (เคสครบ) → `POST /api/cases/:id/cancel` (staff) ได้ **200 status=cancelled** เคสที่ปิดแล้วถูกยกเลิกได้โดยไม่ต้องเปิดใหม่ และเวลาปิดหาย
  - `POST /api/cases/:id/cancel` สองครั้ง → ครั้งที่สองได้ **200** และ logs = `ยกเลิก, ยกเลิก, สร้างเอกสาร`
  - admin `POST /api/cases/:id/reopen` กับเคสที่ open อยู่ → **200** และเพิ่ม log `เปิดงานใหม่` ที่ไม่ได้เกิดขึ้นจริง
- หมายเหตุ: staff ยกเลิกเคสของหน่วยงานตนได้ (ไม่มีข้อกำหนดห้ามใน prompt จึงไม่นับเป็นบั๊ก แต่ควรยืนยัน requirement)

  - `POST /api/cases {"templateCode":"ndmi-consult","data":{...header.receiveDate:"2026-02-30"}}` → **500** และเลขที่เอกสารถูกใช้ไปแล้ว (ผลจริง: ND-2569-00164 → เคสถัดไปได้ 00166 ไม่มี 00165) ขัดกับข้อกำหนดว่าเลขต้องต่อเนื่อง

### B7 — dateField ที่ตั้ง required ไม่ถูกบังคับ — ความรุนแรง: **กลาง**
- สาเหตุ: `server/src/progress.js:62-64` (`missingRequired`) ตรวจเฉพาะ header และ section `type: 'fields'` ไม่ตรวจ `dateField` ของส่วน `checks` ทั้งที่ `server/src/formSchema.js:40` เก็บ `required: true` ของ dateField ไว้ (ผู้ดูแลตั้งบังคับได้ แต่ไม่มีผล)
- ขั้นตอนทำซ้ำ: สร้างฟอร์มด้วย `POST /api/admin/forms` ที่มี `sections[0].dateField = {key:'dd', label:'วันที่ส่งมอบทดสอบ', required:true}` → `POST /api/cases` ด้วย `fields.dd = ''` → ได้ **201** (ควร 400 "กรุณากรอก วันที่ส่งมอบทดสอบ")

### B8 — `data: null` ทำให้ได้ 500 — ความรุนแรง: **ต่ำ**
- สาเหตุ: `server/src/progress.js:25` ใช้ค่า default `input = {}` ซึ่งใช้ได้เฉพาะ `undefined` เมื่อ `input = null` บรรทัด 27 `input.header?.[...]` โยน TypeError (เรียกจาก `index.js:227` และ `index.js:251`)
- ขั้นตอนทำซ้ำ: `POST /api/cases {"templateCode":"<ฟอร์ม>","data":null}` → **500**, `PUT /api/cases/:id {"data":null}` → **500**

### B9 — password ที่ไม่ใช่สตริงทำให้ได้ 500 — ความรุนแรง: **ต่ำ**
- สาเหตุ: `server/src/index.js:25` `bcrypt.compare(password || '', ...)` โยน "Illegal arguments" เมื่อ password เป็นตัวเลข และ `index.js:41,46` ตรวจแค่ `next.length` แล้ว `bcrypt.hash(array)` โยน
- ขั้นตอนทำซ้ำ: `POST /api/auth/login {"username":"test-admin","password":12345678}` → **500** (ควร 401), `POST /api/auth/password {"current":"<ถูก>","next":[1,2,3,4,5,6,7,8]}` → **500** (ควร 400)
